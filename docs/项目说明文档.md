## 1. 项目要解决什么问题

垃圾邮件过滤的目标不是"准确率高"，而是**同时压住两类错误**：

| 错误类型 | 定义 | 业务后果 |
|---|---|---|
| **FP**（误报） | 正常邮件被判为垃圾 | 用户丢失重要邮件，信任度崩塌 |
| **FN**（漏报） | 垃圾邮件被放过 | 垃圾邮件继续进入收件箱 |

本项目因此做三件事：

1. **可靠地把原始邮件变成可比对的文本**（解析、编码恢复、HTML 清洗、去重）
2. **公平地比较两种分类方法**（朴素贝叶斯 vs 逻辑回归）
3. **用真实错误解释模型行为**，并给出可落地的过滤建议

最终在冻结的 5,097 封测试邮件上：**LR 准确率 99.22%，macro-F1 99.16%，误报 11 封，漏报 29 封。**

### 防泄漏是本项目的核心工程约束

课程评分会检查"TF-IDF 是否只在训练集拟合"、"相同内容是否跨集合"。本项目用**四层机制**保证：

**第一层：内容分组整组划分**
相同原始字节、最终文本、有效正文或 HTML 对照文本的邮件构成连通分量，**整组分配到同一个集合**，永不跨集合。

```python
# src/spam_classifier/data_split.py
for groups in buckets.values():
    for group in groups.values():
        for row in group[1:]:
            union(group[0]["mail_id"], row["mail_id"])   # 并查集合并
```

**第二层：开发样本强制进训练侧**
用于调试解析器的 400 封样本其内容已被"看过"，其关联的 372 个分组、1,738 封代表**全部强制进入训练集**，避免把已曝光样本当未见测试数据。

**第三层：词表与 IDF 只在训练集拟合**

```python
# src/spam_classifier/text_features.py
TfidfVectorizer(
    tokenizer=tokenize_text, min_df=2, max_features=50000,
    sublinear_tf=True, norm="l2", dtype=np.float64,
)
# 验证/测试只调用 .transform()，绝不调用 .fit()
```

**第四层：来源指纹链 + 不可变模型锁**
每一层产物的 SHA256 都被下一层校验，任何一环被改动即拒绝加载；第 7 步结束前生成 `final_lock.json`，锁定模型、参数与全部产物指纹，**之后才允许读取测试集**。

```python
# src/spam_classifier/model_inputs.py
if (policy != frozen["split_policy_source_sha256"]
        or parser_sha != cleaning["parser_source_sha256"]
        or cleaning["cache_sha256"] != summary["input_provenance"]["cleaning_cache_sha256"]):
    raise ValueError("Parser or cleaning provenance changed.")
```

### 3.2 解析与清洗（代码要点）

解析顺序是**传输编码 → 字符集 → HTML**，每一步都留有可审计的降级记录。

```python
        candidate = _decode_bytes(raw_value, part.get_content_charset())
        ...
        actions.append("mislabeled_base64_text_fallback")
        return raw_value
```

字符集解码带**候选回退链**和**乱码检测**：

```python
# 候选顺序：BOM → HTML meta → utf-8 → gb18030 → gbk
candidates.extend(hint_codecs + ["utf-8", "gb18030", "gbk"])
for charset in candidates:
    try:
        text = data.decode(charset, errors="strict")
        # 宽容编码可能"成功"解出二进制：控制字符比例超限则跳过
        if _control_count(text) / max(1, len(text)) > CONTROL_LIMIT:
            continue
        return Decoded(text, declared, charset, charset != declared_codec)
    except (UnicodeError, LookupError):
        continue
```

HTML 处理保留文字、丢弃结构：

```python
def html_to_text(text: str) -> str:
    soup = BeautifulSoup(text, "html.parser")
    for node in soup.find_all(["script", "style", "head", "template", "noscript"]):
        node.decompose()
    for node in soup.find_all(string=lambda v: isinstance(v, Comment)):
        node.extract()
    ...
    return soup.get_text(separator=" ", strip=False)
```

文本规范化统一走一个函数，主题与正文共用：

```python
def clean_text(text: str) -> str:
    text = unicodedata.normalize("NFKC", text).lower()
    text = "".join(c for c in text if c in "\n\t" or unicodedata.category(c) not in {"Cc","Cf","Cs"})
    text = URL.sub(" urltoken ", text)      # 网址
    text = EMAIL.sub(" emailtoken ", text)  # 邮箱
    text = PHONE.sub(" phonetoken ", text)  # 电话
    return re.sub(r"\n{3,}", "\n\n", text).strip()
```

### 3.3 清洗结果

| 互斥状态 | 封数 | 含义 |
|---|---:|---|
| `ok` | 29,891 | 常规处理可用 |
| `recovered` | 33,307 | 记录了回退或结构恢复 |
| `subject_only` | 1,422 | 只有主题可用 |
| `quarantined` / `error` | 0 | 本批无隔离 |

> **"技术可用"不等于"语义正确"。** 替换符比例为 0 不能证明没有乱码；private-use 字符会另标质量警告。这一点在第 7 步错误分析中仍然成立。

### 3.4 去重改变了类别构成（重要结论）

| 类别 | 原始占比 | 去重后占比 | 保留率 |
|---|---:|---:|---:|
| ham | 33.68% | 63.00% | **98.37%** |
| spam | 66.32% | 37.00% | **29.35%** |

垃圾邮件的精确重复远多于正常邮件（30,632 封重复记录中绝大多数是 spam）。**因此最终成绩描述的是"不同规范化文本代表"上的表现，不能直接当作自然收件箱的邮件流分布。**

## 4. 特征工程

### 4.1 分词规则（固定且可指纹验证）

- jieba 0.42.1 默认词典，精确模式，`HMM=False`
- 固定停用词表 57 词（训练词频统计**之前**制定）
- 保留：非停用词中文单字、数字、三个占位符
- 丢弃：纯标点、单个英文字母、超 40 字符片段

人工示例（**非真实邮件摘录**）：

```
输入：会议通知：请明天参加项目讨论。
输出：会议 / 通知 / 请 / 明天 / 参加 / 项目 / 讨论

输入：免费会员优惠！访问 urltoken，联系 emailtoken 或 phonetoken。
输出：免费 / 会员 / 优惠 / 访问 / urltoken / 联系 / emailtoken / phonetoken
```

### 4.2 TF-IDF 计算

```
sublinear_tf:  tf = 1 + ln(tf)
smooth_idf:    idf = ln((1 + N_train) / (1 + df_train)) + 1
最终:           L2 归一化 → CSR 稀疏矩阵，float64
```

| 参数 | 值 |
|---|---|
| `min_df` | 2 |
| `max_features` | 50,000 |
| `ngram_range` | (1, 1) |
| `fit_scope` | **train_only** |

训练侧矩阵 23,792 × 50,000，`nnz=3,664,007`，密度 0.31%，三套集合均无空向量。

## 5. 模型与实验设计

### 5.1 候选与选择规则

| 方法 | 参数 | 实现 |
|---|---|---|
| 多数类基线 | 无 | `DummyClassifier(strategy="most_frequent")` |
| 朴素贝叶斯 | `alpha=0.1/0.5/1.0` | `MultinomialNB(force_alpha=True, fit_prior=True)` |
| 逻辑回归 | `C=0.5/1/2` | `solver="liblinear"`, L2, `tol=1e-4`, `max_iter=2000`, `random_state=42` |

**选择规则在运行前就固定**：

```python
# src/spam_classifier/model_selection.py
SELECTION_POLICY = {
    "eligible_rows": "exclude family='majority' and rows where converged is not true",
    "ranking": [
        {"metric": "macro_f1", "order": "descending"},
        {"metric": "ham_false_positive_rate", "order": "ascending"},
        {"metric": "spam_recall", "order": "descending"},
        {"metric": "candidate_id", "order": "ascending_lexical"},
    ],
    "precision": "use exact unrounded metric values",
}
```

> 为什么用 macro-F1 而不是准确率？因为多数类基线准确率 62.99%，却漏掉全部 1,887 封垃圾邮件——准确率在类别不平衡下极具误导性。

### 5.2 指标定义

```python
# src/spam_classifier/model_selection.py
tn = np.count_nonzero((truth == 0) & (prediction == 0))   # 正常判正常
fp = np.count_nonzero((truth == 0) & (prediction == 1))   # 正常判垃圾（误报）
fn = np.count_nonzero((truth == 1) & (prediction == 0))   # 垃圾判正常（漏报）
tp = np.count_nonzero((truth == 1) & (prediction == 1))   # 垃圾判垃圾
```

macro-F1 = (ham_F1 + spam_F1) / 2；分母为 0 时按 0 计（如多数类基线的 spam 精确率）。

## 6. 实验结果

### 6.1 第 6 步：验证集七次实验（5,099 封）

| 方法 | 准确率 | spam 精确率 | spam 召回率 | ham F1 | spam F1 | macro-F1 | ham 误报率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 多数类 ham | 62.99% | 0.00% | 0.00% | 77.30% | 0.00% | 38.65% | 0.000% |
| NB α=1 | 95.25% | 92.95% | 94.33% | 96.22% | 93.63% | 94.93% | 4.203% |
| LR C=1 | 98.53% | 99.08% | 96.93% | 98.84% | 97.99% | 98.42% | 0.529% |
| **NB α=0.1** | 95.88% | 93.47% | 95.55% | 96.71% | 94.50% | 95.60% | 3.923% |
| NB α=0.5 | 95.55% | 93.01% | 95.12% | 96.44% | 94.05% | 95.25% | 4.203% |
| LR C=0.5 | 98.14% | 98.70% | 96.24% | 98.53% | 97.45% | 97.99% | 0.747% |
| **LR C=2（候选）** | **98.86%** | **99.41%** | **97.51%** | **99.10%** | **98.45%** | **98.78%** | **0.342%** |

三组 LR 均在 6–7 次迭代内收敛，无训练警告。

### 6.2 第 7 步：HTML 清洗对照（固定 LR C=2）

| 输入表示 | 准确率 | spam 精确率 | spam 召回率 | macro-F1 | FP | FN | 词表标记 token 占比 |
|---|---:|---:|---:|---:|---:|---:|---:|
| **去标签可读文本** | 98.8625% | 99.4057% | 97.5093% | **98.7753%** | 11 | **47** | 0.0198% |
| 保留 HTML 标签 | 98.8429% | 99.4054% | 97.4563% | 98.7540% | 11 | 48 | 0.2209% |

**结论要克制地说**：去标签 macro-F1 高 **0.0213 个百分点**，验证集只相差 **1 封**邮件（去标签正确、保留 HTML 错误）。实际改变的训练/验证输入只有 156 / 36 封。

> 这**不能**宣称为"显著提升"或"普遍有效"。按预先声明的排序规则锁定去标签表示，仅此而已。标记 token 占比从 0.2209% 降到 0.0198% 只是噪声代理指标，不证明语义改善。

### 6.3 第 8 步：冻结测试集最终评估（5,097 封）

| 模型 | 准确率 | spam 精确率 | spam 召回率 | ham F1 | spam F1 | macro-F1 | ham 误报率 |

混淆计数（每行 `TN+FP=3211`，`FN+TP=1886`，总数 5097）：

| 模型 | TN | FP | FN | TP |

## 7. 错误分析

### 7.1 候选选取规则（固定、与语义叙事无关）

```python
# src/spam_classifier/final_evaluation.py
selected = sorted(indices, key=lambda i: (-abs(float(scores[i])), records[i]["mail_id"]))[:15]
```

即：按模型分数绝对值取前 15 个 FP 与 15 个 FN，mail_id 字典序做确定性 tie-break。**这是高置信度错误样本，不是随机样本，类别计数不能用于估计全部错分的比例。**

### 7.2 诊断统计

| 模型 | 错误类型 | 总数 | 候选 | 含 HTML | 编码警告 | 文本≤30字 |
|---|---|---:|---:|---:|---:|---:|
| NB | FP | 134 | 15 | 12 | 4 | 0 |
| NB | FN | 61 | 15 | 14 | 3 | 12 |
| LR | FP | 11 | 11 | 1 | 0 | 0 |
| LR | FN | 29 | 15 | 3 | 5 | — |

LR 的 11 个误报全部被纳入复核（候选数 = 总数），其中 10 个来自 `recovered` 状态。

### 7.3 语义观察（56 个实例，AI 辅助复核）

**误报（FP）主导模式：招聘/通知与商业推广词重叠**
- 13/15 个 NB 误报、7/11 个 LR 误报属于"招聘通知与商业词重叠"
- 典型：长篇招聘汇总里公司宣传、销售岗位、投递入口与职位介绍交织
- 也有"查分通知含服务推广词"（LR-FP-03、LR-FP-05）：考试查分通知同时介绍付费电话与短信服务

**漏报（FN）主导模式：叙事包裹推广 / 可用文本过短**
- 故事、祝福、笑话、私人聊天包裹推广请求（NB-FN-09~12、LR-FN-05、LR-FN-13）
- 长篇资讯/评论缺少典型促销模式（NB-FN-01、LR-FN-01、LR-FN-02）
- **短文本**：12/15 个 NB 漏报可用文本 ≤30 字；LR 漏报中 6 个是 `subject_only`（只有主题）

> 短文本漏报与 `subject_only` 状态直接相关：可用文本太少时，词袋模型缺少判别信号。这与"清洗阶段技术可用 ≠ 语义足够"的判断一致。

### 7.4 关联词（LR 系数，公开通用词表内）

| 偏向正常邮件 (ham) | 系数 | 偏向垃圾邮件 (spam) | 系数 |
|---|---:|---|---:|
| 学生 | -3.22 | urltoken | +12.20 |
| 工作 | -2.78 | phonetoken | +6.04 |
| 研究 | -1.79 | 免费 | +4.62 |
| 学校 | -1.53 | 邮件 | +4.39 |
| 问题 | -1.16 | 网站 | +4.06 |
| 老师 | -1.03 | emailtoken | +3.96 |

> **高频词 ≠ 分类关键词。** 高频是文档覆盖率（一个词出现在多少封邮件里），LR 系数是模型在给定语料下的条件关联。公开词图只覆盖预先固定的 53 词通用表，不是完整词表的全局排名，也不表示因果。

### 7.5 过滤建议

1. **误拦的邮件应进"可恢复垃圾箱"而非直接删除**——LR 误报集中在招聘与查分通知这类"高价值正常邮件"
2. **短文本与仅主题邮件单独处理**：可加入时间、发件域等结构特征，或直接放行到人工复核
3. **上下文特征补充词袋**：招聘类邮件的正文业务介绍占比是显著混淆源，章节权重可能比纯词频更稳健
4. **不据此重调模型**：本次测试用于解释，后续改进需要新的验证方案与未见测试集

## 10. 局限与结论

### 10.1 结论

在本语料与冻结划分下：

- **LR C=2 明显优于 NB α=0.1**：准确率 99.22% vs 96.17%，误报 11 vs 134，漏报 29 vs 61，两类错误同时改善
- **HTML 去标签方案被保留**，但优势极小（macro-F1 差 0.0213 个百分点，验证集仅 1 封差异），不应过度解读
- **防泄漏设计有效**：内容分组整组划分 + 训练侧独拟合 + 指纹链 + 不可变模型锁，使验证集选参与测试集评估相互隔离

### 10.2 局限（必须如实说明）

1. **历史语料**：TREC 2006 的邮件分布与现代邮箱差异明显，99.22% 不能代表当代真实过滤性能
2. **近重复仍可能残留**：精确去重无法识别所有近重复广告模板——错误分析中"查分通知""招聘汇总"主题相似但正文不同正是例证
3. **类别比例已改变**：去重后 spam 占比从 66.32% 降到 37.00%，评估对象是"不同规范化文本"而非自然邮件流
4. **图片与附件未做 OCR**：HTML 中的图片内容完全不参与特征
5. **词袋模型的固有局限**：叙事包裹推广、短文本样本是当前两类错误的主要来源，词频模型难以捕捉语用层面的意图
6. **错误分析为 AI 辅助复核**：56 个实例已有语义概述，**学生人工签认仍待完成**；这些是内容观察，**不是经反事实验证的错因**

### 10.3 后续改进方向

- 引入结构特征（发件域、邮件路由头、附件类型）作为补充，但必须严守"不进入主模型的既有垃圾评分与身份字段"约束
- 对短文本/仅主题邮件做专门的分流策略
- 采用新的验证方案与未见测试集，任何改进都不能复用本次测试集调参

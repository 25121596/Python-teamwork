# 分词与 TF-IDF 机制说明

以下全部为人工构造的输入，不是实际邮件摘录。真实正文、完整词表、词频及矩阵只保存在本地。

**人工分词示例**

输入：`会议通知：请明天参加项目讨论。`

输出：`会议 / 通知 / 请 / 明天 / 参加 / 项目 / 讨论`

输入：`免费会员优惠！访问 urltoken，联系 emailtoken 或 phonetoken。`

输出：`免费 / 会员 / 优惠 / 访问 / urltoken / 联系 / emailtoken / phonetoken`

输入：`不买，不送；Amount １２３，A。`

输出：`不 / 买 / 不 / 送 / amount / 123`

**固定分词规则**

使用锁定的 jieba 0.42.1 默认词典，精确模式、`HMM=False`。NFKC 与英文小写后，按固定的 [停用词表](../config/stopwords_zh.txt) 去除 57 个通用中英文词；该表在训练词频统计之前制定。

保留非停用词的中文单字（如“不、没、买、送”）、数字，以及 `urltoken`、`emailtoken`、`phonetoken`。去掉纯标点、单个英文字母、不在规定中英文/数字字符范围的片段以及超过 40 字符的词片段。过滤的是 token，不是整封邮件。

占位符保留网址/邮箱/电话出现的信号，不把具体联系方式放入该特征。普通数字保留在本地模型特征中，公开词图不展示数值词。

**TF-IDF 的计算范围**

每个训练 token 的文档频率 df 是“包含该词的训练邮件数”，每封邮件最多为 df 贡献一次。`min_df=2` 去掉只在一封训练邮件出现的词；`max_features=50000` 按训练语料总词频截断。

在词频大于 0 时，sublinear TF 为 `1 + ln(tf)`；平滑 IDF 为 `ln((1 + N_train) / (1 + df_train)) + 1`。相乘后对每封邮件进行 L2 归一化；输出 CSR 稀疏矩阵、float64。

词表和 IDF 只在 train 的 23,792 封代表上拟合；validation/test 仅使用已有词表转换，未知词不新增列。单独验证了转换前后的词表及 IDF 指纹不变，并由独立脚本重算训练侧 df 和 IDF。

**公开词图的范围**

[公开通用词表](../config/public_terms_zh.txt) 在查看本次词频之前固定为 53 个通用词/占位符。只展示总训练覆盖至少 20 封的词，每类按邮件覆盖率排序取前 12 个。这是该预设词表内的高频展示，不宣称它们是整个语料中最高频的所有词，也不等于模型关联词。完整训练词频保存在被忽略的本地目录。

**运行与后续使用**

在仓库根目录执行 `python scripts/build_features.py`，再执行 `python scripts/check_features.py`；具体 Windows 虚拟环境命令见 [第五阶段记录](stages/05_探索分析与文本特征.md)。入口会将本仓库 src 加入模块搜索路径；单独加载 joblib 也必须使用同样的模块路径及固定依赖，并先核对指纹。

当前保存的是特征转换管线，没有分类器。第六步才比较多数类基线、朴素贝叶斯和逻辑回归；第七步对照使用同一划分及 ID 顺序，并为每种文本表示分别在训练集拟合自己的词表/IDF。

参考：[jieba 官方说明](https://github.com/fxsjy/jieba)、[TfidfVectorizer 文档](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)。

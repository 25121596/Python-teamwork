**稳定 ID 与账目口径**

清单字段为：`mail_id`、`relative_path`、`index_order`、`label_name`、`label`、`size_bytes`、`status`、`index_occurrences`。

- `relative_path` 相对语料根，如 `data/000/000`；读取时由 `data_root / relative_path` 定位。
- `index_order` 为原始索引物理行号，从 1 开始。
- `mail_id` 是 `trec06c_` 前缀加路径签名：SHA256 输入为 UTF-8 编码的 `trec06c-path-v1`、一个 NUL 分隔符和规范化相对路径。移动语料根或重排索引，不改变同一路径的 ID。
- ID 标识文件路径，不标识内容；不同路径的相同正文要留待清洗后的内容去重。
- 同路径同标签只输出一份 canonical 记录，同时记录首次行号和出现次数；有标签冲突时不选多数标签，整条唯一记录隔离。
- 唯一记录状态按缺失、非普通文件、stat 失败、空文件、非空标签冲突、有效记录进行归类；状态互斥。冲突与重复统计可和文件问题重叠。

对账等式：物理行数＝空行＋格式错误＋非法标签＋不安全路径＋路径解析错误＋辅助路径行＋接受行；接受行数＝唯一规范化路径数＋重复额外行数；唯一记录数＝各状态数之和。异常明细的条目数不等于异常邮件数，同一邮件可能同时存在冲突、缺失或覆盖问题。

索引摘要保存主索引本身的 SHA256 以追踪输入版本；这不是邮件正文哈希。

**开发样本的选择理由**

默认取 400 封，正常邮件 200 封、垃圾邮件 200 封。使用等量配额是为了第三阶段调试时覆盖两类解析场景；该比例与原始 33.68%/66.32% 的类别比例不同。

先对可用记录按类别与规范化路径固定排序，再使用 Python `random.Random(42).sample` 抽取。样本不足时按可用数量缩减和补配额，不对有问题的文件补抽。本次样本 ID 全部唯一，且都是完整清单的子集。

开发样本只有路径元数据和标签，没有主题、正文或收发件信息。它不是训练/验证/测试划分，不能用开发样本报告最终分类效果。

**验证与审查**

- 人工语料测试共 9 项：8 项执行通过，1 项因本机 Windows 不允许创建符号链接而跳过；跳过项不能宣称已实测通过。
- 已执行的测试覆盖格式/标签错误、空行/CRLF、合法相对路径、越界/绝对路径、缺失、空文件、目录目标、重复别名、冲突、辅助文件、未索引文件、样本可复现及 ID 在语料搬迁和索引重排后稳定。
- 在测试中限制文件打开操作，只允许打开索引；若审计尝试读取邮件正文，测试失败。人工邮件中的私密哨兵字符串未进入任何结果。
- 更换启动工作目录再次运行全量审计，完整清单、异常明细、开发样本及统计摘要的字节级 SHA256 均保持一致。
- 无效样本大小和缺失配置返回退出码 2，不覆盖先前输出；发生此类错误时，旧产物不代表本次运行成功。
- 完整清单与异常明细受 Git 忽略规则保护；公开结果不包含个人绝对路径或邮件正文。

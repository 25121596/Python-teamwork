# 5 分钟汇报讲稿（阶段草稿）

对应《汇报草稿.pptx》8 页，总计划时长 5 分钟；实际语速需彩排计时。当前材料只含真实历史验证结果，必须完成真实清洗对照、最终测试和错分复核后替换相应内容，再录制正式课程视频。成员姓名与实际分工由小组确认后加入开场和结尾。

## 第 1 页 · 0:00—0:25 · 中文垃圾邮件分类

大家好，我们的项目是中文垃圾邮件分类。目标是把原始邮件整理成可靠的文本特征，比较朴素贝叶斯和逻辑回归，同时关注误拦正常邮件和漏掉垃圾邮件的代价。本次材料展示已有的数据处理与验证实验；清洗对照和最终测试尚待真实数据恢复后执行，下面所有模型成绩都属于验证集。

依据：项目计划.md；artifacts/metrics/model_selection.json

## 第 2 页 · 0:25—1:05 · 去重改变了语料的类别构成

课程提供的 TREC06C 主索引有六万四千六百二十封邮件，其中垃圾邮件约占百分之六十六点三。我们只使用 full/index，delay/index 涉及相同邮件，不能拿来当独立测试集。清洗后全部邮件技术可用，按相同内容去重后剩三万三千九百八十八封代表。正常邮件保留约百分之九十八点四，垃圾邮件只保留百分之二十九点三，说明垃圾邮件的精确重复更多。去重后垃圾邮件占百分之三十七，因此这里评估的是不同文本代表，而不是实际收件箱的自然邮件流。

依据：artifacts/audit/eda_summary.json；artifacts/audit/index_summary.json

## 第 3 页 · 1:05—1:35 · 解析与清洗保留完整质量记录

邮件处理先解传输编码，再按字符集解码，并记录回退。MIME 多部分只选合适的正文，避免纯文本和 HTML 重复拼接，也跳过附件。HTML 去掉脚本和样式，保留可读文字，再归一化常见联系字段。最终约三万封常规解析成功，三万三千多封经过恢复，一千四百二十二封只有主题可用。这里的可用只是技术可读，不能证明语义完全正确，也不能把没有替换符当作没有乱码。

依据：docs/stages/03_邮件解析与全量清洗.md；artifacts/audit/cleaning_summary.json

## 第 4 页 · 1:35—1:55 · 按内容分组冻结训练、验证与测试

相同正文、原始字节或对照文本关联的邮件整组划分，防止同一内容同时出现在训练和测试中。调试解析器接触过的开发样本及其关联组固定到训练侧。训练约二万三千八百封，验证和测试各约五千一百封。训练学特征与模型，验证选方案，测试只用于最后评估。

依据：artifacts/audit/split_summary.json；docs/stages/04_去重与冻结数据划分.md

## 第 5 页 · 1:55—2:35 · 训练侧 TF-IDF 与两种分类模型

中文先用 jieba 精确分词，关闭 HMM，使用固定停用词。TF-IDF 同时考虑某个词在这封邮件里的出现情况，以及它在训练语料中是否过于常见；再把向量归一化。五万维词表和 IDF 只能在训练集拟合，验证和测试只能转换。朴素贝叶斯用词的类别分布判断邮件，逻辑回归联合学习词权重。我们给两者相同的样本和特征规则，各比较三个参数，并加入多数类作为最低参照。选参优先看 macro-F1，再看正常邮件误报率和垃圾邮件召回率。

依据：docs/分词与特征说明.md；src/spam_classifier/text_features.py；artifacts/metrics/model_selection.json

## 第 6 页 · 2:35—3:40 · LR C=2 在现有验证集上表现最好

这里是五千零九十九封验证邮件的真实历史结果。多数类准确率接近百分之六十三，但它把全部垃圾邮件都漏掉，所以不能只看准确率。朴素贝叶斯最佳 alpha 为零点一，macro-F1 约百分之九十五点六；逻辑回归最佳 C 为二，macro-F1 约百分之九十八点七八。右下的混淆计数显示，逻辑回归把十一封正常邮件误拦为垃圾邮件，漏掉四十七封垃圾邮件；对应正常邮件误报率约百分之零点三四。与朴素贝叶斯的一百二十六次误报相比，它更好地保护了正常邮件。这些结果支持把 LR C 等于二作为下一步候选，但参数是在验证集上选择的，不能把这组数当作最终测试成绩。

依据：artifacts/metrics/stage06_validation.csv；artifacts/audit/model_validation.json

## 第 7 页 · 3:40—4:25 · 清洗效果与错因需要独立证据

下一步清洗对照固定 LR C 等于二、相同训练验证样本及其他配置，只改变是否去除 HTML 标签。真实对照还没运行，因此暂时不能宣称去标签一定提升效果。最终方案锁定后才计算测试成绩，再分别检查误报和漏报。程序已能为 NB 和 LR 各选最多十五个误报和十五个漏报候选，但真实文本必须私下阅读，公开时只能用审核后的安全概述。另外，高频词只表示经常出现，LR 系数才反映模型里的分类关联；公开词图只覆盖预设通用词表，不能当成完整词表的排名。

依据：docs/stages/07_HTML清洗对照与方案锁定.md；docs/stages/08_最终测试与错误分析流程.md；artifacts/figures/stage05_training_word_coverage.png

## 第 8 页 · 4:25—5:00 · 结论、局限与复现入口

目前可以确认，编码和结构恢复需要质量记录，去重会明显改变类别构成，而 LR C 等于二在现有验证集上优于本轮 NB 候选。局限包括旧语料、可能残留的近重复模板，以及验证选参带来的乐观偏差。后续将恢复真实数据，完成清洗对照、最终测试和人工错分分析，再补齐成员实际分工与正式报告。代码、聚合证据和各阶段记录均由 Git 管理，仓库链接见屏幕。感谢大家。

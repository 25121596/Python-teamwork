# 3 分钟答辩准备

回答以真实记录为准。以下问题可轮流演练；正式答辩前补齐第七、八步实测与每名成员的实际承担。

| 问题 | 可用的回答要点 | 仓库证据 |
|---|---|---|
| 为什么选 NB 和 LR？ | 两者适合稀疏文本；NB 简单且快，LR 联合学习词的线性权重。共用划分、文本与特征配置，比较才公平。 | `model_selection.json`、第六阶段记录 |
| TF-IDF 在做什么？ | 结合词在当前邮件中的出现和它在训练文档中是否常见；经常出现于所有邮件的词通常较难区分类别。词表/IDF 只用训练集学习。 | `text_features.py`、分词与特征说明 |
| 为什么只看准确率不够？ | 验证多数类准确率 62.99%，却漏掉全部 1,887 封垃圾邮件。还应看 spam 精确率/召回率、两类 F1、macro-F1 及正常误报率。 | `stage06_validation.csv` |
| FP、FN 分别是什么？ | spam 为正类；FP 是正常邮件被误拦，FN 是垃圾邮件被漏掉。LR C=2 现有验证 FP=11、FN=47；这不是最终测试结果。 | 验证 CSV 的 tn/fp/fn/tp |
| 为何不能把 delay 当测试集？ | 它涉及与 full 相同的邮件路径，不是独立新样本；必须从主索引按固定内容分组划分。 | 第二阶段审计与项目计划 |
| 如何避免数据泄漏？ | 内容关联组不跨集合；开发样本触及的组进入训练侧；词表与 IDF 仅训练拟合；验证选参；最终锁通过独立验收后才看测试分类效果。 | 第四、五、七、八阶段 |
| 为什么去重后垃圾邮件比例下降？ | 原始 spam 有更多精确重复，保留代表后的类别构成改变。不能称作随机过滤损失，也不能当作自然收件箱分布。 | `eda_summary.json` |
| 清洗解决了哪些问题？ | 传输编码、字符编码、MIME、HTML 和空文本分别处理，记录异常和回退。技术可读不保证语义完全正确。 | `cleaning_summary.json`、人工清洗示例 |
| HTML 清洗提高了多少成绩？ | 真实对照尚未运行，暂不能回答数值。计划固定 LR C=2 及相同训练/验证 ID，只改变是否去标签，比较预先定义的指标。 | 第七阶段记录 |
| 高频词就是分类关键词吗？ | 高频表示覆盖率高；模型系数反映分类关联，两者不同。公开词图又限定在预设通用词表内，不能当完整词表全局排名。 | 第五、八阶段 |
| 错分案例怎么选，为什么？ | 对 NB/LR 各按置信绝对值选最多 15 个 FP 与 15 个 FN，同分按 ID；便于确定性复核，不是错误总体的随机样本。真实审核尚待执行。 | `final_evaluation.py` |
| 为什么不直接把测试集用于调参？ | 这样会让测试成绩参与选择而偏乐观，无法再代表未见样本效果。程序保存最终锁和测试访问记录，禁止换锁后重选。 | `experiment_io.py`、`evaluate_final.py` |
| 128 个测试通过说明什么？ | 说明人工微型文本上的指定逻辑与边界通过检查，不说明真实语料已复现、模型有 128 次真实实验或最终分数已生成。 | `tests/`、第八阶段记录 |
| 你本人做了什么？ | 各成员按实际代码、分析、复核、讲解填写，并展示自己的真实提交。不得把建议 A/B/C 分工或自动化辅助提交当作学生贡献。 | 成员分工、Git 历史 |

## 建议演练

每人各用 30 秒解释一个方法问题和一个结果问题，剩余一分钟互相追问“依据在哪个文件”。能指出具体数值、适用范围和复现入口，比背诵模型定义更有帮助。

# 3 分钟答辩准备

以下是备选问题，不是在三分钟内逐题讲完。答案已经补入真实实验；成员应能解释自己的实际工作并指出证据。

| 问题 | 回答要点 | 仓库证据 |
|---|---|---|
| 为什么选 NB 和 LR？ | 都适合稀疏文本。NB 用类别词分布，LR 联合学习线性权重；使用相同样本与特征配置比较。NB 选 α=0.1，LR 选 C=2。 | `model_selection.json` |
| TF-IDF 做了什么？ | 同时衡量词在当前邮件中是否突出，以及它在训练文档中是否过于常见。词表和 IDF 仅在训练集学习，验证与测试只转换。 | `text_features.py`、分词与特征说明 |
| 为什么不能只看准确率？ | 最终多数类准确率 63.00%，却漏掉全部 1,886 封垃圾邮件；必须同时看两类 F1、spam 精确率/召回率和正常误报率。 | `stage08_test.csv` |
| 最终结果怎样？ | LR 准确率 99.22%、macro-F1 99.16%、spam 精确率 99.41%、召回率 98.46%。正常类误报率 0.34%；本批测试优于 NB，不代表实际收件箱性能。 | `final_evaluation.json` |
| FP、FN 是什么？ | spam 为正类。FP 是正常邮件被误拦，FN 是垃圾邮件漏过。最终 LR FP=11、FN=29；NB FP=134、FN=61。验证 LR 的 FN=47 是另一集合，不能混用。 | 第八阶段、两张测试混淆矩阵 |
| 为什么不用 delay/index 作测试？ | 它涉及与 full 相同的邮件，不是新的独立样本。只从主索引按固定内容分组划分。 | 第二阶段审计 |
| 如何降低泄漏风险？ | 相同内容关联组不跨集合；开发样本关联组进训练；词表和 IDF 只训练拟合；验证选参；最终锁验收后才读测试成绩。近重复仍可能残留，不能说彻底杜绝泄漏。 | 第四、五、七、八阶段 |
| 为什么去重后 spam 比例下降？ | 原始垃圾邮件精确重复更多，保留代表后占比从约 66.32% 降至 37.00%。评估不同规范化文本，不能把这比例当成自然邮件流分布。 | `eda_summary.json` |
| 清洗解决什么，零隔离是否完美？ | 处理传输编码、字符编码、MIME、HTML 和空文本；记录恢复与仅主题状态。技术可用不等于语义正确，正文中仍能观察到乱码。 | `cleaning_summary.json`、真实错分分析 |
| HTML 清洗提升了多少？ | 验证 macro-F1：去标签 98.7753%，保留 HTML 98.7540%，差约 0.0213 个百分点。仅一封预测不同，去标签少漏一封。两臂输入实际不同的训练/验证样本为 156/36，不能宣称统计显著或普遍有效。 | `cleaning_ablation.json` |
| 高频词等于分类关键词吗？ | 高频是文档覆盖率，LR 系数是模型条件关联。公开图只展示固定通用词表，不是完整词表全局排名，也不表示因果。 | 第五、八阶段 |
| 真实错误有什么特点？ | 56 个模型错误实例按分数绝对值选取，同一邮件可能出现两次；AI 核对主题、正文，长文看首中尾选段，仍待成员确认。可见招聘通知误报、仅主题漏报、小说或私人聊天包裹推广。不是随机样本，不用类别计数估计总体比例。 | `error_review_assisted.json`、真实错分分析 |
| 128 项测试说明什么？ | 验证指定程序逻辑和边界，不等于 128 次真实实验。真实成绩另由固定语料运行及独立验收证明；两个证据层次分开。 | `tests/`、`final_evaluation_validation.json` |
| 为什么跨平台复现略有差异？ | 主索引、清洗、冻结划分一致；词表截断和 IDF 指纹不同，两个非最优 NB 配置各差一封误报，最佳 NB/LR 指标不变。同频截断排序是可能原因，缺少旧私有词表不能证明。没有为凑一致改参数；新运行在测试前独立锁定。 | `restoration_validation.json`、第六 c 阶段 |
| 你本人完成了什么？ | 按实际代码、分析、复核、讲解和真实提交回答。AI 辅助提交不冒充三位学生贡献。今后改参数须用新的验证方案和未见测试集，不能把本次测试当调参集。 | 成员分工、Git 历史 |

## 演练与备查

每人用约 30 秒解释一个方法问题和一个结果问题，再互相追问“证据在哪个文件”。三分钟现场问答通常只覆盖其中几项。优先熟悉混淆矩阵四格、HTML 对照的微小差异、TF-IDF 拟合范围和自己的真实承担。

本轮续作已按阶段留下真实 Git 提交；GitHub 应用写入被 403 阻塞，不能回答“所有更新已经上传”。授权恢复或组员使用自己的合法 Git 登录后，可按交付说明同步完整分支。
